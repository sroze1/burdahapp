SECURITY FIRST — GITIGNORE (before generating any secrets):

Add these entries to .gitignore: android/key.properties, *.jks, *.p12, *.keystore, and ios/**/*.mobileprovision. This prevents signing secrets from ever being committed (threat T-04-04).

DEPENDENCIES:

Run flutter pub add --dev flutter_native_splash flutter_launcher_icons. These are build-time codegen tools, not runtime dependencies — they go in dev_dependencies matching the convention used for flutter_lints in this project.

NATIVE SPLASH CONFIG (flutter_native_splash.yaml):

Create flutter_native_splash.yaml in the project root. Set color and color_dark to "#000000" (matching the SplashScreen's Colors.black background from Plan 01, so the pre-engine native splash is visually seamless with the Flutter splash). Set fullscreen: true. Add an android_12 section with color: "#000000" and color_dark: "#000000" (per RESEARCH Pitfall 2 — Android 12 requires its own config section). Do NOT set any image key — the native splash is color-only per RESEARCH Anti-Patterns (the Madinah photo belongs in the Flutter widget, not the native layer). Run dart run flutter_native_splash:create to generate the native resources.

APP ICONS (flutter_launcher_icons config):

Add a flutter_launcher_icons section to pubspec.yaml (or create a separate flutter_launcher_icons.yaml — either works, pubspec is more conventional for this project). Set android: true, ios: true, image_path: "assets/icon/app_icon_source.png", and remove_alpha_ios: true (iOS marketing icon requires no alpha channel). Run dart run flutter_launcher_icons to generate all icon density variants. Visually inspect the generated output in android/app/src/main/res/mipmap-hdpi/ to confirm the icon is not stretched or cropped.

ANDROID RELEASE SIGNING:

Generate an upload keystore using the JDK bundled with Android Studio (system java/keytool is not installed on this machine): "/Applications/Android Studio.app/Contents/jbr/Contents/Home/bin/keytool" -genkey -v -keystore ~/upload-keystore.jks -keyalg RSA -storetype JKS -keysize 2048 -validity 10000 -alias upload. Use "BurdahApp" as the common name when prompted.

Create android/key.properties with four entries: storePassword, keyPassword, keyAlias (upload), and storeFile pointing to the keystore path. This file is already in .gitignore from the first step.

Modify android/app/build.gradle.kts to load signing config from key.properties. Import java.util.Properties and java.io.FileInputStream. Create a keystoreProperties val that loads from rootProject.file("key.properties"). Add a signingConfigs block with a "release" config reading keyAlias, keyPassword, storeFile, and storePassword from keystoreProperties. Set the release buildType's signingConfig to signingConfigs.getByName("release"). Guard the load with an if (keystorePropertiesFile.exists()) check so debug builds still work without key.properties. Follow the exact pattern from RESEARCH.md Code Examples section.

STORE LISTING METADATA:

Create a store_listing/ directory in the project root. Write three files:

store_listing/play_store_description.txt — Google Play listing with short description (max 80 chars) and full description. App name per D-09: "BurdahApp". Category: Books & Reference. Content rating: Everyone.

store_listing/app_store_description.txt — App Store listing with subtitle, description, and keywords. Same app name and category alignment.

store_listing/privacy_policy.md — Privacy policy placeholder stating the app collects no personal data, requires no account, makes no network requests, and stores no user information. This satisfies the minimum privacy-policy requirement for both stores.

Both store descriptions should convey the app's purpose: a beautiful Islamic poetry reading experience featuring the Burdah of Sayyida Khadija RA with an animated Bismillah splash and Qari Abdul Basit recitation. Tone should be reverent and straightforward. Per D-09, the listing name is "BurdahApp".
