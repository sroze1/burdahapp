# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Stack note:** BurdahApp is a Flutter app (Android + iOS), not a React/web stack. The `shadcn` design-system tooling described in this template's tool-strategy is not applicable — there is no `components.json`, no npm registry, no Radix/base-ui. This contract expresses the same design tokens (spacing, typography, color, copy) in Flutter-native terms (`ThemeData`, custom widgets, bundled fonts) so it remains equally prescriptive for the executor.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Flutter app; design system implemented via `ThemeData` (`ColorScheme`, `TextTheme`) + custom reusable widgets, not a component-registry tool |
| Preset | not applicable |
| Component library | Flutter Material widgets, theme-driven (not Radix/base-ui — not applicable) |
| Icon library | Material Icons (utility/navigation chrome: back arrow, menu, etc.) + custom SVG geometric motifs via `flutter_svg` (decorative border/star-tessellation assets, per D-07) |
| Font | **Scheherazade New** (display/heading — traditional Naskh, most calligraphic; used for the Bismillah/title-style text) + **Amiri** (body/label — classical Naskh, higher readability at small sizes). Both bundled as local assets via `google_fonts`' build-time bundling helper with `GoogleFonts.config.allowRuntimeFetching = false` (per CLAUDE.md — app must never fetch fonts at runtime or show a fallback-font flash). Final choice between Scheherazade New / Amiri / Reem Kufi is verified on this phase's test screen per CONTEXT.md discretion note — if shaping bugs appear (letter-joining breaks, diacritic clipping) on the pinned Flutter/Skia version, fall back to Amiri for display use too before locking. |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, inline padding |
| sm | 8px | Compact element spacing, card-frame border inset |
| md | 16px | Default element spacing, screen-edge padding |
| lg | 24px | Section padding, gap between geometric border and content |
| xl | 32px | Layout gaps between major blocks |
| 2xl | 48px | Major section breaks (e.g. above/below the test screen's font-preview block) |
| 3xl | 64px | Page-level spacing (top of full-screen frame to first content element) |

Exceptions:
- **Icon-only touch targets: 44px minimum** (accessibility floor per platform HIG/Material guidance) — not on the 8-pt scale, applies to any tappable icon-only control (e.g. back button).
- **Geometric border SVG stroke widths** (hairline trim strokes, e.g. 1–3px) are exempt from the 8-pt scale — these are asset-internal stroke fidelity values, not layout spacing.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | Regular (400) | 1.6 |
| Label | 14px | Regular (400) | 1.4 |
| Heading | 24px | Bold (700) | 1.3 |
| Display | 32px | Bold (700) | 1.25 |

Only 2 weights declared (Regular 400, Bold 700) — do not introduce Medium/SemiBold variants. Body and Display line-heights are intentionally more generous than the template's generic 1.5/1.2 defaults (1.6 / 1.25 vs 1.5 / 1.2) because Arabic diacritics (tashkīl) and the ascenders/descenders of calligraphic Naskh forms clip easily at tighter line-heights — verify this visually on the test screen with real diacritic-heavy text (not just plain Arabic letters) before treating as final.

Font-family mapping: Display and Heading roles use **Scheherazade New**; Body and Label roles use **Amiri**. Any incidental Latin/English UI text (e.g. a stray English label) inherits the same role sizes/weights but may render in the platform default sans (San Francisco / Roboto) rather than forcing the Arabic font onto Latin glyphs — confirm Amiri/Scheherazade New Latin-glyph coverage on the test screen; if coverage is poor, this fallback is expected, not a bug.

## Color

Both light and dark themes are in scope for v1 (D-03) — this is more design surface than the template's single-theme default, declared explicitly below.

### Light Theme (default)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FAF6EA` (warm ivory — deliberately not sterile `#FFFFFF`, per D-01) | Screen backgrounds, the reading/content area — kept clean, no pattern (per D-05) |
| Secondary (30%) | `#0A642B` (Islamic green, user-specified exact value, D-01) | Headers, nav/app bar fill, geometric border-frame stroke color, section divider bars |
| Accent (10%) | `#C9A227` (antique/muted gold — illuminated-manuscript tone, not a bright `#FFD700`) | **Reserved for:** primary CTA button fill, divider hairlines between sections, icon-highlight accents, inner trim line of geometric border frames. Nothing else. |
| Destructive/Error | `#B3261E` (muted red) | Error banners/icons only — v1 has no destructive user actions (no delete/logout/reset), so this exists solely for load-failure states |

Text (light): primary `#1B2B20` (near-black, slight green undertone — not pure black, to stay warm/cohesive with the palette), secondary/muted `#5B6B5E`, text-on-green (nav bar labels) `#FAF6EA`, text-on-gold (CTA button label) `#1B2B20`.

### Dark Theme

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0A642B` (the same Islamic green — deliberately used as the dark background itself, per D-03) | Screen backgrounds |
| Secondary (30%) | `#12793A` (lighter green tint, for elevation contrast against the darker base) | Headers, nav/app bar fill, elevated card surfaces, border-frame stroke color |
| Accent (10%) | `#E3C067` (brightened gold — lifted in lightness/saturation vs. the light-theme gold to hold contrast against a dark green background) | Same reserved elements as light theme: primary CTA fill, divider hairlines, icon accents, border trim |
| Destructive/Error | `#E2726B` (lightened red) | Error banners/icons only |

Text (dark): primary `#F5EFDD` (warm off-white, per D-03 "lighter text" — not stark `#FFFFFF`), secondary/muted `#C9D6C9`, text-on-accent (gold CTA button label) `#1B2B20` in both themes for consistent contrast.

**Accent reserved for:** primary CTA button fill, section divider hairlines, icon-highlight accents, and the inner trim line of geometric border/frame widgets — explicitly NOT for body text, backgrounds, list-item fills, or more than one CTA per screen. This is a narrower reservation than "all interactive elements" by design (per D-02, gold is a secondary/illuminated-accent color, not the primary interactive color — green carries most structural/interactive weight).

**Accessibility flag for executor:** gold-on-cream (`#C9A227` on `#FAF6EA`) and gold-on-green (`#C9A227`/`#E3C067` on `#0A642B`/`#12793A`) contrast ratios have not been numerically verified against WCAG AA in this research pass — run both combinations through a contrast checker during Phase 1 execution before shipping the CTA button; adjust gold luminance (not hue) if either combination fails 4.5:1 for text or 3:1 for large-text/UI-component contrast.

|---------|------|

Please restart the app, or reinstall it if the problem continues."** — for a bundled-offline app (ARCH-01), a load failure is a packaging/asset problem, not a network one, so copy should not suggest "check your connection" |
| Destructive confirmation | **Not applicable in v1** — no delete, logout, reset, or other destructive user actions exist anywhere in the current requirement set (v1 scope has no accounts, no user-generated data to destroy) |

| populated | Test/demo screen renders real catalog JSON + chosen font + full color palette together | ✅ covered | This is exactly Phase 1 success criteria #2 and #3 — both require the populated, correctly-rendered state to be visible and verified before the phase can be signed off. |
